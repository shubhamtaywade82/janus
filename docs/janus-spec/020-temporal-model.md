# JDS-020: Temporal Synchronization Model
Version: 1.0
Status: Approved

Janus operates across multiple temporal domains. This specification defines time domains, latency measurements, and clocks synchronization.

```
 [Exchange Matcher (Exchange Time)] ---> [Network Latency] ---> [System Clock (Local Time)]
                                                                           |
                                                                           v
                                                               [Virtual Clock (Replay Time)]
```

## 1. Time Domains

### 1.1 Exchange Time ($T_{	ext{ex}}$)
- **Source**: Transaction timestamps generated by exchange matching engines (e.g. Binance matching time).
- **Format**: Unix epoch milliseconds.
- **Characteristics**: Immutable historical anchor.

### 1.2 System Clock ($T_{	ext{sys}}$)
- **Source**: Local server time synchronized using Network Time Protocol (NTP).
- **Precision**: Sub-millisecond tracking.
- **Standard**: Coordinated Universal Time (UTC).

### 1.3 Replay Time ($T_{	ext{rep}}$)
- **Source**: Virtual clock driving historical backtesting.
- **Mechanism**: Advanced programmatically on event sequence number, decoupled from real time.

---

## 2. Clock Drift & Latency Guards
To prevent trading on stale data, feed latency ($\Delta_{	ext{lag}}$) is monitored continuously:

$$\Delta_{	ext{lag}} = T_{	ext{sys}} - T_{	ext{ex}}$$

- **Latency Limits**:
  - If $\Delta_{	ext{lag}} > 1000	ext{ms}$ on Level 2 depth: flag data feed as degraded.
  - If $\Delta_{	ext{lag}} > 2000	ext{ms}$ on OrderBook updates: suspend strategy scoring, reject new entries.
