# 📄 JDS-000.4: MetaConstraint Logic Expression Specification
Version: 1.0.0
Status: DRAFT
Owner: Compiler Architecture

## 1. Core Philosophy: Abstracting Logic
In the Janus Meta-Model (`janus-meta`), a **`MetaConstraint`** represents a rule of physics that the system must enforce. To ensure that constraints are independent of target languages, the expression of a constraint is not represented as raw code strings (e.g., JavaScript or Python expressions).

Instead, expressions compile down to a canonical **Logic Tree AST (Abstract Syntax Tree)** format. The Physics Solver (`janus-physics`) traverses this tree at compile-time to prove invariants, or compiles the tree nodes into runtime assertion guards.

---

## 2. Logic Tree AST Grammar

The Logic Tree is composed of `LogicalNode` blocks. Each node has a type, operator, and operands:

```typescript
export type LogicalNode =
  | OperatorNode
  | ComparisonNode
  | VariableNode
  | LiteralNode;

export interface OperatorNode {
  type: 'OPERATOR';
  op: 'AND' | 'OR' | 'NOT';
  operands: LogicalNode[];
}

export interface ComparisonNode {
  type: 'COMPARISON';
  op: 'GT' | 'GTE' | 'LT' | 'LTE' | 'EQ' | 'NEQ';
  left: LogicalNode;
  right: LogicalNode;
}

export interface VariableNode {
  type: 'VARIABLE';
  path: string; // e.g. "entity.upperPrice" or "tick.price"
}

export interface LiteralNode {
  type: 'LITERAL';
  value: string | number | boolean;
}
```

---

## 3. Representation Example: `Law_of_Causality`

To illustrate, consider the constraint `entity.createdAt >= entity.provenance.interactionTrigger.createdAt`. 

In the JIR/FKIR manifest, this constraint is serialized as the following Logic Tree AST:

```json
{
  "constraintId": "physics.temporal.Law_of_Causality",
  "scope": "relationship.causal.MitigatedBy",
  "severity": "FATAL",
  "expression": {
    "type": "COMPARISON",
    "op": "GTE",
    "left": {
      "type": "VARIABLE",
      "path": "entity.createdAt"
    },
    "right": {
      "type": "VARIABLE",
      "path": "entity.provenance.interactionTrigger.createdAt"
    }
  }
}
```

## 4. Compile-Time Evaluation & Optimization

During the compiler pipeline passes:
- **Constant Folding**: The compiler checks if any branch of the Logic Tree resolves to a static constant (e.g., `5 > 3`). If so, it simplifies the node.
- **Static Proofs**: If the scope defines components with strict bounds (e.g., `upperPrice > lowerPrice`), and the comparison tree asserts `upperPrice >= lowerPrice`, the Physics pass statically resolves the tree to `true` and skips generating runtime checks.
