# 📄 JDS-000.1: Specification Language Syntax (JDS Grammar)
Version: 1.0.0
Status: DRAFT
Owner: Compiler Architecture

## 1. Core Philosophy: A Dedicated Grammar
The Janus Domain Specification (JDS) is defined using a dedicated, statically-typed financial modeling language. We do not use YAML for our core language files. YAML suffers from implicit typing issues, indentation ambiguities, and weak editor integration. 

Instead, the `.jds` grammar is custom-built to borrow the readability of modern system languages (e.g. Rust, Kotlin) while enforcing explicit declarations of modules, imports, facets, lifecycles, and domain physics.

---

## 2. JDS Concrete Grammar Syntax Reference

The following is the formal syntax mapping for `.jds` source modules:

```jds
// ontology/imbalance/FairValueGap.jds
module ontology.imbalance.FairValueGap@1.2.0;

import ontology.primitives.Candle@^1.0.0;
import ontology.lifecycle.Finite@^2.0.0;
import systems.mitigation.MitigationSystem@^1.0.0;

object FairValueGap {
    facets {
        domain: Imbalance;
        spatial: Zone;
        lifecycle: Finite;
        execution: Tradable;
    }

    data {
        upperPrice: float;
        lowerPrice: float;
        direction: enum(BULLISH, BEARISH);
        detectedAt: timestamp;
    }

    lifecycle {
        states: [FORMING, DETECTED, ACTIVE, INTERACTING, RESOLVED, ARCHIVED];
        outcomes: [MITIGATED, INVALIDATED, EXPIRED];
    }

    affordances {
        entry;
        confluence;
        target;
    }

    evidence_requirements {
        PRICE_OVERLAP required_for INTERACTING;
    }
}
```

## 3. Lexical Tokens

The `.jds` Lexer tokenizes the source code into the following primitives:
- **Keywords**: `module`, `import`, `object`, `relationship`, `system`, `law`, `facets`, `data`, `lifecycle`, `states`, `outcomes`, `affordances`, `evidence_requirements`, `required_for`.
- **Identifiers**: Fully qualified path strings (e.g. `ontology.imbalance.FairValueGap`).
- **Verbatim Versioning**: `@` marker followed by SemVer ranges.
- **Braces & Semicolons**: Block structure markers `{ }`, `;`.
