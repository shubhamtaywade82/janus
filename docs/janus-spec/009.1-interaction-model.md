## 1. Core Philosophy: Transient Interactions vs. Persistent Relationships
In the Janus Temporal Knowledge Operating System (TKOS), we make a strict distinction between **Interactions** and **Relationships**:
- **Interactions** are transient, dynamic market events that occur between two or more entities (e.g., price touching a FVG boundary, or volume delta crossing an Order Block). They represent active physical processes, are short-lived, and contain high-frequency execution data.
- **Relationships** are persistent, event-sourced semantic links created and evolved as a direct *consequence* of those interactions (e.g., the FVG is now `MITIGATED_BY` the price action).

By placing Interactions between Objects and Relationships, we avoid creating static, brittle edges and instead preserve the complete causal lineage of why a relationship exists.

```
┌──────────────────┐       ┌─────────────────┐       ┌────────────────────┐
│  Market Object   │ ─────>│   Interaction   │ ─────>│    Relationship    │
│  (Passive Node)  │       │ (Transient Event)│       │ (Persistent Edge)  │
└──────────────────┘       └─────────────────┘       └────────────────────┘
```

## 2. Interaction Taxonomy (The Physics of Touch)

Interactions are detected by specialized realtime systems (e.g., `InteractionSystem`) and are grouped into families:

### 2.1 Spatial Interactions
- **`Touch`**: Price wicks or trade ticks reach the exact boundary of a spatial zone (e.g., candle high matches FVG low).
- **`Penetration`**: Price penetrates into the body of a zone but does not close beyond it.
- **`Overlap`**: Two independent zones share a coordinate space (e.g., FVG and OB overlapping price levels).
- **`Containment`**: One zone completely encloses the boundary of another.
- **`Cross`**: A curve or dynamic line crosses another line (e.g., price crossing EMA200, or fast EMA crossing slow EMA).

### 2.2 Order Flow & Delta Interactions
- **`Retest`**: Price returns to a zone with high passive depth, showing bid/ask interaction.
- **`Consumption`**: Volume absorbs the liquidity inside a zone (e.g., aggressive market buy orders clearing ask depth at a resistance block).
- **`Competition`**: Two zones compete for order execution (e.g., equal highs pulling liquidity from opposite directions).

## 3. The `Interaction` Contract

Every interaction is an immutable fact recorded in the event stream and mapped to the active session.

```typescript
export interface MarketInteraction {
  id: string;                       // UUID v7 (Time-sortable)
  type: 'TOUCH' | 'PENETRATION' | 'CROSS' | 'RETEST' | 'CONSUMPTION';
  
  // The entities involved
  sourceEntityId: string;           // e.g., FVG ID or PriceTick ID
  targetEntityId: string;           // e.g., OrderBlock ID
  
  // Interaction physics
  timestamp: ExchangeTime;          // Precise exchange timestamp
  price: number;                    // Price at which the interaction occurred
  volume?: number;                  // Vol/delta during interaction
  deltaImbalance?: number;          // CVD delta during interaction
  
  // Provenance
  detectedBy: string;               // e.g., 'RealtimeInteractionSystem'
  evidenceEvents: string[];         // Level 0 source event IDs (Ticks, Trades)
}
```
