# 📄 JDS-003.4: Market Object Facet Model Specification
Version: 1.0.0
Status: DRAFT
Owner: Core Architecture

## 1. Core Philosophy: The Multidimensional Signature
In the Janus Market Operating System, a Market Object (entity) is not defined by a single type or rigid class hierarchy. Instead, it is characterized by a **Facet Signature**—a set of orthogonal, semantic descriptors representing different dimensions of market reality.

Decoupling identity from behavior allows:
- **Queryability**: The Strategy Engine, Graph Builder, and AI can query the Knowledge Graph for dynamic confluences using generic semantic signatures (e.g. finding all `Zone` geometric nodes that are `Tradable` and `Imbalance`-related).
- **Extensibility**: Adding new market objects requires only defining their Facet Signature. The existing processing systems instantly know how to interact with them without code changes.
- **Entity-Component-System (ECS) Mapping**: Objects are passive facts (Entities) containing signatures and coordinate data (Components). Logic lives entirely in independent processing pipelines (Systems).

## 2. The Facet Dimensions

Every `MarketObject` in the Janus AST must declare its values across these independent axes:

### 2.1 Domain Facet
Defines which market data vertical the object belongs to.
- **`Structure`**: Trend bias, swings, shifts, and pivots (e.g., `SwingHigh`, `BOS`).
- **`Liquidity`**: Areas of structural orders and stop clusters (e.g., `LiquidityPool`, `StopCluster`).
- **`Imbalance`**: Supply/Demand inefficiencies (e.g., `FairValueGap`, `OrderBlock`).
- **`Volume`**: Volume profiles and shelves (e.g., `HighVolumeNode`, `POC`).
- **`OrderFlow`**: Active aggression and market delta (e.g., `Absorption`, `Spoofing`).
- **`Volatility`**: Volatility states and regimes (e.g., `VolatilityRegime`).
- **`Derivatives`**: Derivatives positioning metrics (e.g., `FundingCluster`, `OICluster`).
- **`Session`**: Session temporal boundaries (e.g., `NYSession`).

### 2.2 Semantic Facet
Defines the epistemological role of the object.
- **`Observed`**: Direct, raw facts from the exchange.
- **`Derived`**: Mathematical or structural transformations of raw facts.
- **`Structural`**: Establishes physical support, resistance, or structural pivot zones.
- **`Behavioral`**: Reflects active participant behavior and flows.
- **`Statistical`**: Represents statistical distributions and deviations.
- **`Predictive`**: Provides leading indications of potential future price reactions.
- **`Reactive`**: Validates structural changes after they occur.

### 2.3 Trading Facet
Defines how the object participates in a trade thesis.
- **`Entry`**: Localization zone for entering a trade.
- **`Confirmation`**: Validation catalyst for confirming a setup.
- **`Target`**: Destination target for the trade.
- **`Stop`**: Region for defining stops.
- **`Invalidation`**: Boundary where the trading thesis is disproven.
- **`Context`**: Broad environment filter (e.g., higher timeframe trend).
- **`Bias`**: Directional bias filter.

### 2.4 Spatial Facet
Defines the geometric footprint of the object.
- **`Point`**: Single price-time coordinate.
- **`Range`**: 1-dimensional horizontal price level.
- **`Zone`**: 2-dimensional boundary (price range $\times$ time range).
- **`Curve`**: Non-linear mathematical boundary.
- **`Network`**: Graph topology of interconnected nodes.

### 2.5 Temporal Facet
Defines the horizon of the object's relevance.
- **`Instant`**: Valid for a single tick or trade.
- **`Session`**: Valid for the duration of a trading session.
- **`Swing`**: Valid across minor swing points (hours).
- **`Trend`**: Valid across major trends (days).
- **`Macro`**: Valid across institutional horizons (weeks).

### 2.6 Lifecycle Facet
Defines how the object persists over time (see `003.3-object-lifecycle-model.md`).
- **`Persistent`**: Remains active until swept or explicitly resolved.
- **`Finite`**: Natural decay curve; expires if not tested.
- **`Continuous`**: Updates dynamically without terminal resolution.
- **`Episodic`**: Forcefully resolved at a fixed temporal boundary.
- **`Composite`**: Lifecycle is a derived function of child component states.

### 2.7 Execution Facet
Defines how the Execution Engine interacts with the object.
- **`Tradable`**: Can be used to anchor execution orders.
- **`Protective`**: Can be used to set stop losses.
- **`Targetable`**: Can be used to anchor take profit targets.
- **`Monitorable`**: Can be tracked in real-time.

### 2.8 Confidence Facet
Defines the mathematical/inference model of the object.
- **`Deterministic`**: Explicit, mathematically clean logic.
- **`Probabilistic`**: Statistical distribution model.
- **`Heuristic`**: Heuristic ruleset or pattern matching.
- **`AI_Inferred`**: Derived by AI neural networks or LLMs.

## 3. Object Signatures Examples

The Strategy and Execution engines reason over signatures rather than hardcoded classes:

### 3.1 Fair Value Gap (FVG)
```yaml
signature:
  domain: [Imbalance]
  semantic: [Derived, Structural, Predictive]
  trading: [Entry, Confirmation]
  spatial: [Zone]
  temporal: [Swing]
  lifecycle: [Finite]
  execution: [Tradable]
  confidence: [Deterministic]
```

### 3.2 Liquidity Pool
```yaml
signature:
  domain: [Liquidity]
  semantic: [Derived, Structural, Predictive]
  trading: [Target, Context]
  spatial: [Zone]
  temporal: [Trend]
  lifecycle: [Persistent]
  execution: [Targetable]
  confidence: [Probabilistic]
```

### 3.3 Swing Low
```yaml
signature:
  domain: [Structure]
  semantic: [Derived, Structural, Reactive]
  trading: [Stop, Invalidation]
  spatial: [Point]
  temporal: [Swing]
  lifecycle: [Persistent]
  execution: [Protective]
  confidence: [Heuristic]
```
